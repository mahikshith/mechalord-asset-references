# Iron March gameplay truth audit

Audited 7 October 2026 on `codex/iron-front-unbroken-campaign`, starting at checkpoint `24664c4`. Follow-up implementation was committed as `89d971a`; its normal-runtime observations are recorded separately in [gameplay-animation-fixes.md](gameplay-animation-fixes.md). This audit separates source verification, isolated previews, automated control and normal-player observations. The earlier all-checked feature list overstated completion.

**The combat systems are substantially implemented. The nineteen requests are not all accepted or fully verified in normal play.** In particular, the checkpoint's allied troops used static mesh instances with whole-body bobbing and yaw, not articulated walking or strafing. The promised urgency, animation quality, sound quality and art quality cannot be established by passing code tests.

## Concrete integration corrections from this audit

- Correct the clash-win toast: winning applies damage and does not guarantee a component broke. Source now says **TYRANT HIT**.
- Describe Endurance as **relic + burst duration**. It does not extend Freeze, Slow, Haste or every temporary weapon.
- Fixed-value campaign gates must not tell the player to shoot to improve their values. Normal campaign guidance now says to choose a recruiting gate.
- Visible laser timing instructions must be in the normal HUD, not only an accessible label or review controller. Source now exposes line-up, wait and counter stages, and disables LASER while another burst prevents firing it.
- Boss absorption must be a visible normal-player sequence before calling the authoritative reward operation. Source now tracks one pending choice, holds the reward phase, supports pause, cancels on menu/restart, and saves the final imprint only after the core accepts it.
- A paused clash stopped its audio source but remembered it as playing. Source now clears the cue latch/cooldown when silenced, so it can restart on resume.

These source corrections are not a replacement for the requested fresh normal-browser check. The follow-up UI test receipt supersedes its earlier 15-group receipt only for UI/audio source behavior; historical rendered receipts still describe their own build identities.
